# K' Library コンテンツ制作スキル

## このスキルの目的

K' Library（`books/` 配下）に、視覚的に読者を引き込むビジュアル・エッセイページを追加する。
**「読んだことない人が、読みたくなる」**ことが唯一の成功基準。

---

## 制作フロー

### Step 1：コンセプトメモを先に出す（制作前に必ず）

ページを作る前に、必ず以下のフォーマットでコンセプトメモを提示しユーザーの承認を得る。

```
📖 **タイトル（著者／監督）**

**入口**：この作品で一番意外・鋭い切り口を一行で

**核心**：「〜の話ではない。〜の話だ」という形で本質を言い切る

**デザイン方向**：どんな視覚体験にするか（色・構造・感情のアーク・スクロール体験）
```

提示後「制作しますか？」と一言添える。ユーザーがGOを出してから制作に入る。

### Step 2：HTML ページ制作（技術仕様は後述）

### Step 3：`books/index.html` に背表紙を追加（後述）

### Step 5：公開後の集客を提案（「公開後の集客」参照）

## コンテンツ選定の方針

ユーザーから作品指定がない場合、以下を意識して自分で選ぶ。

- **ジャンルを循環させる**：小説→ノンフィクション→映画→テーマ考察→…と偏らないようにする
- **デザインの個性を出しやすい作品を選ぶ**：強い感情的コア、鮮明なビジュアルイメージ、逆説的な核心を持つ作品
- **入口を探す**：有名な事実ではなく、知られていない角度・逆説・感情的な瞬間から始める
- **既存の書架と重複しない**

## デザイン設計の原則

### やってはいけないこと

❌ あらすじ→登場人物→テーマ→引用 の定型構成
❌ 情報を「整理」するページ（Wikipediaの改良版になってしまう）
❌ 同じカラーパレット・レイアウト構造の使い回し
❌ 「評論家の読み＋デザイナーの判断」という固定フレームで毎回同じ思考をする

### やるべきこと

✅ **その作品固有の感情のアーク**を設計する
✅ **スクロールが感情体験になる**構造を作る
✅ **毎回異なる入口**から設計する（入口の例は下記参照）
✅ **テキストを最小化し、視覚に語らせる**

### 入口の探し方（毎回変える）

以下は入口の候補。毎回同じパターンを使わないこと。

| 入口の種類 | 例 |
|---|---|
| 一番意外な事実 | ワイルズが証明発見の瞬間に泣いた |
| 読後3日後に残るイメージ | 屋根裏部屋にひとり |
| 作品の逆説・矛盾 | 「失格」と呼ばれた男を誰も責めなかった |
| 読者が感じる抵抗感 | 難しそう、暗そう、自分には関係なさそう |
| 著者の偏執・執念 | 7年間誰にも言わなかった |
| 唯一の感情的ピーク | 「生涯でもっとも美しい瞬間だった」 |

## HTML 制作の技術仕様

### 基本方針

- **単一HTMLファイル**（CSS・JS すべてインライン）
- 外部ライブラリ・フレームワーク不使用
- `books/` 配下に配置（例：`books/fermat.html`）

### 毎回変えるべき要素

- 背景の質感・色温度（暗闇、原稿用紙、宇宙、etc.）
- タイポグラフィの扱い（縦書き、タイプライター、崩れていく、etc.）
- セクションの数と感情的な流れ
- アクセントカラー（作品の感情温度に合わせる）
- アニメーションの有無・種類

### 既存ページから学んだパターン（これらと違う構造を毎回作ること）

**フェルマーの最終定理（`fermat.html`）**
暗闇→光へ向かう構造。方程式が1.8秒後に点灯。5章構成（出会い・孤独・欠陥・閃光・余白）。

**人間失格（`ningen-shikkaku.html`）**
原稿用紙グリッドを背景に。タイプライターで冒頭の一行。スクロールで文字が傾き崩れていく。塗りの「笑」と輪郭だけの「笑」の対比。

### 必須要素

```html
<!-- スクロール出現 -->
<div class="reveal">...</div>
<!-- IntersectionObserver で .in クラスを付与 -->

<!-- prefers-reduced-motion 対応 -->
@media(prefers-reduced-motion:reduce){ ... }

<!-- フッターに書架への導線 -->
<a href="index.html">◂ 書架へ戻る</a>
```

## `index.html` 背表紙の追加

### CSS（`.b-{id}` 形式）

```css
.b-{id}{
  background: linear-gradient(90deg, {暗め}, {メイン}, {暗め});
  width: {44〜58px};
  height: {230〜270px};
}
.b-{id} .ttl, .b-{id} .label, .b-{id} .top {
  color: {作品のアクセントカラー};
}
```

### HTML（該当 `.shelf` の `.row` 内に追加）

```html
<a class="book b-{id}" href="{filename}.html">
  <span class="top">{著者名}</span>
  <span class="ttl">{タイトル}</span>
  <span class="label">{ジャンル一言}</span>
</a>
```

**棚の振り分け：**
- `物語 と 探究 / Tales & Inquiry`：小説・テーマ考察・ノンフィクション
- `映画評論 / Cinema`：映画・アニメ
- 新ジャンルは新しい `.shelf` を追加してよい

## アフィリエイト方針（収益化・必須）

各ページ末尾（**フッター直前**）に、楽天＋Amazon の2系統CTAを必ず設置する。

### 原則
- **2系統併設**：楽天（ユーザーが `a.r10.to` 短縮リンクを発行して渡す）＋ Amazon（検索リンク・自動生成可）
- **PR表記は必須**（景表法・ステマ規制 2023.10〜）：「※本リンクは楽天・Amazonアフィリエイトを含みます（PR）」を必ず添える。隠すと違法
- リンクは必ず `target="_blank" rel="sponsored noopener"`
- ボタン色は**そのページのアクセントカラー**に合わせる（Amazonボタンだけは橙 `#FF9900→#E47911` で固定）
- リンク先は**その作品の本・円盤など関連性の高い商品のみ**（無関係な商品に飛ばさない＝信頼維持）
- 動詞：本＝「読む」／映画・アニメ＝「観る」／テーマ考察＝「見る」

### Amazon リンクは自動生成できる
**Store ID は `kplab-22` 固定**。タイトル＋著者をURLエンコードして検索リンクにする：
```
https://www.amazon.co.jp/s?k={URLエンコードした「タイトル 著者」}&tag=kplab-22
```

### 楽天リンクはユーザーに依頼
楽天は商品ごとにリンク発行が必要 → 制作時に**「この作品の楽天リンク(a.r10.to)を」とユーザーに尋ねる**。
未取得ならAmazonだけ先に入れ、楽天は後差し（プレースホルダ）でよい。

### CTAテンプレート（フッター直前に配置）
```html
<div style="max-width:720px;margin:40px auto 0;padding:26px 24px 0;text-align:center;border-top:1px solid {ACCENT_a18};">
  <div style="font-size:12px;letter-spacing:.14em;color:{ACCENT};margin-bottom:12px;">{この作品にふれる 等の一言}</div>
  <a href="{楽天 a.r10.to}" target="_blank" rel="sponsored noopener"
     style="display:inline-flex;align-items:center;gap:8px;text-decoration:none;font-weight:800;
     background:linear-gradient(135deg,{ACCENT},{ACCENT_DARK});color:{暗色};padding:14px 30px;border-radius:10px;">
     🛒 楽天で{読む/観る} →</a>
  <a href="https://www.amazon.co.jp/s?k={ENC}&tag=kplab-22" target="_blank" rel="sponsored noopener"
     style="display:inline-flex;align-items:center;gap:8px;margin:8px 0 0 10px;text-decoration:none;font-weight:800;
     background:linear-gradient(135deg,#FF9900,#E47911);color:#16120a;padding:14px 26px;border-radius:10px;">
     🛒 Amazonで{読む/観る} →</a>
  <div style="margin-top:11px;font-size:11px;color:{MUTED};">※本リンクは楽天・Amazonアフィリエイトを含みます（PR）</div>
</div>
```

### Amazon運用の注意（最初に一度だけ確認）
- アソシエイト管理画面に公開サイト（`gor565.github.io`）が**登録済みか**
- 登録後**180日以内に適格販売3件**が必要（未達だと未承認）。楽天は審査なしなので、その間も楽天側で回る

## 公開後の集客（X / note 誘導）

作って公開しただけでは読まれない。**収益は流入で決まる**。公開後、ユーザーに以下を提案する。

### 導線
**X（認知）→ note（深掘り）→ books ページ（作品体験＋アフィリ）** の順で流す。K'既存の X(@kp_rei_)／note を再利用。

### Xポスト案（公開ごとに1本）
- フック＝そのページの「入口」をそのまま1行に（事実／逆説／感情のピーク）
- ヒーローのスクショを添付（縦長 or 16:9）
- 末尾に books ページURL。誘導句は短く
- 宣伝臭を消し「読み物」として差し出す。タグ2〜3個

### note案
- ページの世界観を文章で補う短い導入 → 末尾「ビジュアル版はこちら」で books へ

### 計測（任意）
- **Cloudflare Web Analytics**（無料・Cookieレス）を1スニペット入れれば、どの作品が読まれ・押されたか分かる → 次の選書に反映

## 品質チェック（公開前・必須）

- [ ] **可読性**：本文が動く背景の上で読みにくくなっていないか（暗い下地／影で必ず可読に。過去に背景が文字を潰した失敗あり）
- [ ] **センシティブ／疑似科学テーマは両論併記**：断定せず出典を明示し「これは仮説」と明記（例：日ユ同祖論）
- [ ] **アフィリCTA＋PR表記**が入っているか
- [ ] **prefers-reduced-motion** 対応
- [ ] **index.html に背表紙追加**＋リンクが実体ファイルに解決するか
- [ ] スマホ幅で崩れないか
